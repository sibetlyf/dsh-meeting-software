# DSH × Yogurt 会议助手

`dsh-meeting-software` 已经是带 DSH 集成的 Yogurt 分支。融合采用一个 Electron 应用和一个 DSH meeting Profile，不同时启动两套桌面会议助手。

| 阶段 | 主责 | 失败时的行为 |
| --- | --- | --- |
| 会前 | DSH 处理自然语言调度；桌面日程事件日志负责执行。邀请、单次和每日任务可留在同一个界面。 | DSH 未启动也可执行已在本地的日程；单次任务最多补触发 15 分钟。应用须处于运行状态。 |
| 入会 | 现有日程允许明确选择「加入已有会议」或「发起快速会议」。Windows 腾讯会议优先通过自己的入会窗填写并核验会议号；快速会议用客户端的发起控件。 | 找不到控件时提示在客户端接管，并继续检测（窗口探测可用时）。旧日程缺少会议号或链接时不会发起新会。 |
| 会中 | 勾选自动录音的日程由 Windows 会中窗口探测触发 Yogurt 录音、实时逐字稿和笔记。 | 两次匹配才触发；90 秒未确认时保留手动记笔记入口。不自动录音的日程只发起入会。 |
| 会后 | 连续五次有效探测未发现原会中窗口时，停止此日程启动的录音。现有流水线组织百炼精转、声纹、四象限纪要、归档和知识库。 | 单轨精转失败可使用该轨的实时稿；模型失败保留可读文本；知识库未确认时保留会议制品，不显示同步成功。 |

DSH 插件在 `DSH_MEETING_DESKTOP_SCHEDULER=1` 时停止自己的轮询入会，继续提供日程工具、原生会话、制品和健康接口。自然语言调度与会议分析走不同通道：纪要使用 DSH 配置的模型直连，不把逐字稿作为具备执行工具的 Agent 指令。原生笔记等待同一次会后处理，不重复生成纪要。独立 Soulmirror 会控仍可手动使用，但同一场会不要与桌面端同时录制。

会后制品照常归档；知识库写入由 DSH meeting Profile 的 `dshKnowledge.ingestRecord` 完成，桌面不再写知识库文件夹。插件不可用时，本地归档不受影响。

## 不使用 DSH：自动记录已经开始的会议

从项目根目录运行 `pnpm start --without-dsh`。在 Yogurt 中将「检测到会议时自动进入笔记」设为「自动」或「弹窗确认」，然后像平常一样打开腾讯会议或支持的移动云会议客户端并进入会议，也可以先入会再打开 Yogurt。无需建日程或连接 DSH。

Yogurt 运行期间持续检测；连续两次确认同一会中窗口后，「自动」会打开会议笔记并启动录音，「弹窗确认」会先询问，「关闭」不触发。手动结束或选择跳过后不会重复处理同一场；若能读到会议号，同一会议号在本次 Yogurt 运行期间也不会重复触发。有可验证的会议号时会填入标题；客户端没有暴露会议号时，不阻止录音。只打开客户端或停在等候室不会触发录音。本地探针超时会重试，不会当作会议已结束。DSH 插件的知识库同步不属于独立模式。 连续确认的会议还会写入本地「今日日程」，标记为「自动检测」，不触发入会；关闭自动进入笔记或跳过录音不影响此记录。当天同平台、同会议号的已有日程不会重复新增。

## 启动与验收

如需对比 CMD 启动的 DSH 和内置 DSH，先正常退出 Yogurt。在项目的 `app` 目录，用项目的 `.dsh-home` 和 `DSH_MEETING_DESKTOP_SCHEDULER=1` 单独启动 `dsh --profile meeting --no-open --port 3090`。保持 DSH 运行，在另一个终端将它打印的完整本机地址赋给 `YOGURT_DSH_EXTERNAL_URL`，再从项目根目录运行 `pnpm start`。地址里的 token 不要分享。该模式不会启动第二个 DSH，也不会在退出 Yogurt 时关闭外部实例；移除该环境变量后恢复内置模式。

内置 DSH 以 `dsh --profile meeting --no-open --port 3090` 启动（端口可由 `DSH_MEETING_PORT` 指定），并仅在子进程环境设置 `DSH_PERMISSION_MODE=danger-full-access`。项目的 `meeting` 配置同样明确选择 `danger-full-access` 作为默认预设。此设置不提升 Windows 权限，也不修改腾讯会议数据目录权限。

1. 正常退出旧 Yogurt 窗口和手动启动的同端口 DSH。在项目根目录运行 `pnpm build`、`pnpm start`。Windows 启动器直接启动项目的 `meeting` Profile，待健康检查通过后再启动 Electron；两个进程由同一个启动器管理，不需要提前启动外部 DSH。启动终端保持运行，正常退出 Yogurt 后，启动器会关闭本次启动的内置 DSH。
2. Windows 启动器只在验证旧 DSH 属于本项目且未录音时自动迁移。无法验证或正在录音时保留旧进程；结束录音后重新启动 Yogurt。其他占用 `3090` 的服务不会被关闭。新版退出时会自动停止自己启动的 DSH。
3. 确认会议客户端已安装、已登录，且已获得录音许可。创建测试日程，填入会议号或官方邀请链接，勾选「入会确认后自动录音」，点击加入或等待到点。
4. 在等候室确认不录音，入会后检查麦克风、系统音频和逐字稿；退出后检查是否自动停止，以及桌面制品和 DSH 知识库的实际状态。

## 边界与后续

- Windows 自动识别依赖客户端窗口类与标题，不等同于平台提供的会话状态。浏览器会议、其他系统、没有可识别窗口的客户端和部分升级版本需手动开始笔记。
- 自动录音不代表完全离线。当前生产路径的实时及会后语音识别依赖百炼；摘要可能发送文字给 DSH 配置的模型服务。正式使用前应确认凭据、音频设备和数据授权。
- 这是按日程触发的闭环，不会绕过会议密码、主持人审批或系统权限。知识库失败时本地仍留档，但尚无持久重试队列；会后发布到团队和为参会者创建外部任务也不在默认自动化范围内。
- 真机验收优先覆盖腾讯会议的正常入会、等候室、最小化、退出，移动云会议的不同版本，以及 DSH 不可达、无百炼凭据、单音轨和知识库不可达。
